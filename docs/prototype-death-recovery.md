# 死亡流程前置研究：单快照事务与重试原型

原型只存在于 Gradle 的 testFixtures 源集，不进入生产 JAR，也不发布测试夹具变体。只验证游戏无关的事务恢复。输入是稳定 UUID 与合成字符串；没有死亡或登录钩子，不读写玩家档，不选择任何玩法，不接入注册入口。

## 选型

| 方案 | 结论 |
| --- | --- |
| [现有 M1-02 持久化](m1-02-persistence.md) | 复用其设计边界：不可变值、过期观察值拒写、同目录暂存后发布，以及损坏或未来版本不当作缺失。原型只声明适配器接口；未连接 SavedData，也未假定它已有跨玩家档和模组存档的事务能力。 |
| [JDK NIO 同目录原子移动](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/nio/file/Files.html#move(java.nio.file.Path,java.nio.file.Path,java.nio.file.CopyOption...)) | 仅在测试夹具使用。沿用 Java 25 平台 API，不增生产依赖。测试按单写者顺序复开同一临时目录；NIO 原子移动不能替代跨进程并发锁，平台不支持时测试不降级。 |
| [数据库预写日志](https://www.postgresql.org/docs/current/wal-intro.html) | 仅参考“先持久记录、后恢复”的思路。完整数据库会增加许可审查、维护、部署、安全和 I/O 成本，也不能令独立的 Minecraft 存档自动参与事务。本原型没有引入或复制外部实现。 |

## 契约与验证

同一 UUID 与请求内容只向前推进：缺失 → PREPARED → APPLIED → COMMITTED。APPLIED 把**合成结果和标记放在同一份快照**；COMMITTED 保留该结果。单键整份比较并发布，遇到竞争重读，遇到 I/O 错误不当作缺失，未知写入结果由调用方用同一 UUID 与同一请求重试。请求冲突拒绝写入。已结束记录在重试窗口内必须保留；本原型不定义回收策略。

JUnit 验证已完成不重写、不同请求拒绝复用、失去写入竞争后重读、存储契约破坏、失去写入确认、格式损坏拒写。测试夹具还启动独立 JVM，分别在三个阶段原子发布后直接 halt，然后从磁盘重开并检查恢复只写尚缺的阶段。该测试是进程中断，不是整机断电、断电耐久性或并发生产写入测试。

下一步需要另行验证 Minecraft 服务端生命周期、版本化 snapshot 适配器，以及与独立玩家存档之间的故障窗口。不能将合成结果的幂等重试视作玩家物品、传送、重生或跨文件副作用的 exactly-once 保证。
