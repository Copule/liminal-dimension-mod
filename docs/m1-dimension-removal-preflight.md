# 缺失维度预检：先看玩家档，再决定是否移包

M1-06 的实机结果证明：维度未注册时，原版可先选回退世界，再独立沿用玩家档中的旧坐标。成功登录并不证明落点安全；之后的保存也可能改写原位置。这里交付的是**停服副本上的只读预检工具**，不改变游戏逻辑、不改玩家档、不能在运行中拦截登录，也不替代冷备份或恢复方案。

## 用法（Minecraft Java 26.3 专用服务器）

1. 停服并保留已校验的全量冷备份。另复制一份供检查；不要扫描正在写入的世界，也不要将副本当作唯一备份。
2. 在另一个不接受真实玩家登录的隔离实例中，按计划的移包后环境启动相同版本和配置，确认**实际仍能加载**的维度键。可以用服务端控制台对候选键执行 `execute in <id> run time query gametime`，区分命令成功和找不到维度；不要用玩家登录去试。将经验证的键以 JSON 字符串数组写入 `target-dimensions.json`，例如只有默认维度时：

   ```json
   ["minecraft:overworld", "minecraft:the_nether", "minecraft:the_end"]
   ```

   上述仅为格式示例，必须验证本次实际配置。预检不推断模组、数据包加载顺序或有效注册表；不要把未验证的 ID 填进去。少列一个实际存在的维度可能阻断，多列一个实际不存在的维度可能掩盖风险。
3. 用 Python 3.12+ 在该停服副本运行：

   ```sh
   python tools/dimension_preflight/preflight.py /path/to/stopped-world-copy target-dimensions.json
   ```

| 退出码 | JSON 状态 | 如何解释 |
| --- | --- | --- |
| 0 | `NO_MISSING_REFERENCES_FOUND` | 在本副本、所给维度清单及已知格式内，未发现主玩家档引用缺失维度。**不是安全许可**：不验证落点、世界健康、备份完整性或未来变动。 |
| 1 | `BLOCK` | 至少一项引用缺失或玩家档不能验证。先不要移包或开放登录；核对维度清单及可恢复备份，再决定怎样安全迁移。 |
| 2 | `INPUT_UNVERIFIED` | 无法确认世界目录、格式或目标清单；不要当成无风险。 |

默认报告不输出玩家 UUID、输入路径、坐标或档案内容。需要在本机定位时，可附加 `--show-files`（包含玩家 UUID，不应直接公开原始输出）。序号基于扫描排序，不是稳定玩家 ID。按审慎原则，无主档或主档无法解析时，即使 `.dat_old` 存在也会阻断；有效主档存在时，旧档不影响主档的维度引用判断，亦不被读取。扫描不会安装/移除任何内容、尝试修复、对活跃存档加锁，或代替系统管理人员完成操作。

## 技术依据和边界

- [M1-05](m1-05-dimension-removal.md) 显示旧维度区块目录可能仍留在磁盘，且有效数据包维度不保证出现在序列化的 `world_gen_settings.dat`。所以这里不将目录、区块或序列化世界设置当成权威目标维度清单。
- [M1-06](m1-06-client-dimension-travel.md) 的代码检查解释了 `PrepareSpawnTask` 的回退和 `PlayerDataStorage` 主档/旧档行为。独立核对了 [Mojang 26.3 正式发布说明及服务端 JAR](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3#get-the-release)：JAR SHA-1 对应官方对象 `33680f5f2ac32864d6d7cf5e56a705fdb3e05f4c`，内置 `version.json` 确认世界版本 5023；类常量复核到 `players/data`、`Dimension`、`.dat_old`。本工具只接受对应版本的 NBT 和布局；需要数据修复器的旧版档案、单人世界格式、非标准文件、缺失必需元数据、符号链接或超限输入均不会清除阻断。副本本身必须完整；遗漏主档及其备份的玩家无法被自动发现。
- 候选一是沿用 M1-05 的 [nbtlib](https://github.com/vberlier/nbtlib) 2.0.4。它维护通用读写接口、许可证兼容且已经用于实验取证，但该版本短读数值会返回 0，足以让缺少结束标记的主档被当成正常；它的 Compound 还会覆盖重复键。候选二是调用 NeoForge/原版解析器并读取真实运行时注册表，语义更直接，但离线预检会引入 Java 25、游戏加载、版本适配和更多写入面。现阶段采用一个仅抽取少量字段的 Python 标准库只读解析器：限制压缩/展开大小和深度，校验结构、长度与重复键，不运行游戏，不复制外部代码，无新依赖或服务端常驻开销。升级世界版本前需要重新核对布局、命名键和实际存档。
- 本轮验收使用合成 NBT 测试（包括失效主档、有效旧档、可加载的嵌套标签、截断但 CRC 正确的 NBT、CRC 损坏、重复标签、扩容限制、错误版本、缺失清单、隐私与只读）。未用真实玩家原档运行，不声称自动预检已写入生产流程。

```sh
python -m unittest discover -s tools/dimension_preflight -v
```
